## 2024-04-16 - Missing Admin Authorization on Master Whiskey Data
**Vulnerability:** Any authenticated user could create, edit, or delete entries in the master `Whiskey` global directory because `Create.cshtml.cs`, `Edit.cshtml.cs`, and `Delete.cshtml.cs` under `Pages/Whiskies` lacked authorization attributes. Only the `/Admin` folder was protected by convention.
**Learning:** Razor Pages convention-based folder authorization (`AuthorizeFolder("/Admin")`) does not automatically protect administrative-level entities that reside outside the designated admin folder.
**Prevention:** Always explicitly annotate page models with `[Authorize(Roles = "Admin")]` for global entity modification pages, regardless of folder structure.

## 2024-06-17 - SSRF and Path Traversal in Image Fetching
**Vulnerability:** The application allowed users to supply an arbitrary `GooglePhotoUrl` which `HttpClient.GetAsync` fetched without validating the host or scheme, enabling Server-Side Request Forgery (SSRF) and potentially exposing internal network services. In addition, file upload handling preserved the original `ImageUpload.FileName` directly in the generated filename, potentially enabling directory traversal attacks.
**Learning:** External URLs provided by users must always be strictly validated against an allowlist of expected hosts and schemes. Default `HttpClient` behavior auto-follows redirects which can be abused to bypass initial host checks. Using user-supplied filenames directly in server file paths is a risk even when concatenated with UUIDs if they contain sequence like `../`.
**Prevention:** Use `Uri.TryCreate` to ensure absolute URIs, explicitly verify the scheme is HTTPS, and enforce that the host belongs to trusted domains (e.g., `*.googleusercontent.com`). Disable `HttpClient` auto-redirects (`HttpClientHandler { AllowAutoRedirect = false }`). When saving uploaded files, extract only the extension using `Path.GetExtension()` instead of appending the entire original filename.
