## 2024-04-16 - Missing Admin Authorization on Master Whiskey Data
**Vulnerability:** Any authenticated user could create, edit, or delete entries in the master `Whiskey` global directory because `Create.cshtml.cs`, `Edit.cshtml.cs`, and `Delete.cshtml.cs` under `Pages/Whiskies` lacked authorization attributes. Only the `/Admin` folder was protected by convention.
**Learning:** Razor Pages convention-based folder authorization (`AuthorizeFolder("/Admin")`) does not automatically protect administrative-level entities that reside outside the designated admin folder.
**Prevention:** Always explicitly annotate page models with `[Authorize(Roles = "Admin")]` for global entity modification pages, regardless of folder structure.

## 2025-02-28 - SSRF Vulnerability in Google Photos Integration
**Vulnerability:** The application was vulnerable to Server-Side Request Forgery (SSRF) when fetching images via a user-provided `GooglePhotoUrl`. The `HttpClient` made a GET request to an arbitrary URL while unconditionally appending a `Bearer` token. Furthermore, it automatically followed redirects, allowing an attacker to exfiltrate the token to a malicious server or probe internal network endpoints.
**Learning:** `HttpClient` automatically follows redirects by default. If it is used to fetch user-provided URLs while attaching sensitive headers (like Bearer tokens), an attacker can supply a benign-looking URL that redirects to a malicious server, leaking the token. Simply checking the URL scheme and domain is insufficient if automatic redirects are enabled.
**Prevention:** Always validate user-provided URLs strictly (checking both scheme and host). For `HttpClient` instances that handle user-provided URLs, specifically when appending authorization headers, instantiate them with a custom `HttpClientHandler` configured with `AllowAutoRedirect = false` to prevent token leakage via malicious redirects.
